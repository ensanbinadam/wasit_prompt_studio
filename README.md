# وسيط | Wasit Prompt Studio

استوديو عربي وإنجليزي لبناء برومبتات مفصلة، مع مكتبة أوامر وقوالب وإعدادات للمخرجات الرقمية وتذييل اختياري لبيانات المعلم أو الباحث.

- [فتح الموقع المنشور](https://ensanbinadam.github.io/wasit_prompt_studio/)
- [مستودع المشروع على GitHub](https://github.com/ensanbinadam/wasit_prompt_studio)

> يبني وسيط البرومبت ويجهزه للنسخ أو التنزيل. إنتاج الملفات النهائية مثل PDF وDOCX وPPTX يعتمد على أدوات منصة الذكاء الاصطناعي التي تنفذ البرومبت.

## المميزات

- **136 أمرًا** في **9 تصنيفات**.
- **11 قالبًا سريعًا** لتعبئة الفكرة والإعدادات بنقرة واحدة.
- حقول تتكيف مع مهام القصص والتعليم والبرمجة والبحث والمرئيات.
- مكتبة شخصيات للقصص المصورة، منها شخصية سالم.
- تحديد صيغ المنتج المطلوب، ومنها PDF وDOCX وPNG وSVG وHTML وPPTX وXLSX وZIP وMP3 وMP4 وCSV وJSON وMarkdown.
- تذييل مستقل لبيانات مثل اسم المعلم والمدرسة، مع خيارات للمحاذاة والحجم والنطاق.
- تدقيق للبرومبت يعرض الملاحظات وأزرار إصلاح لبعض الحالات.
- واجهة عربية وإنجليزية، واتجاه نص قابل للتخصيص، ومظهر فاتح وداكن.
- حفظ القوالب في المتصفح، واستيراد المكتبة وتصديرها بصيغة JSON.
- نسخ البرومبت وتنزيله كنص، وتصدير صفحة HTML للبرومبت الحالي.
- روابط لفتح البرومبت في منصات خارجية، وتكامل اختياري مع Gemini عبر الخادم.

## طرق الاستخدام

### 1. الموقع المنشور

افتح [وسيط على GitHub Pages](https://ensanbinadam.github.io/wasit_prompt_studio/). تعمل صياغة البرومبت والبحث والقوالب والحفظ المحلي داخل المتصفح.

**GitHub Pages يستضيف الواجهة فقط.** ميزتا اختبار البرومبت مع Gemini وتوسيع الفكرة تحتاجان إلى خادم يشغل `server.ts` ومفتاح خدمة صالح.

### 2. الملف المستقل

افتح `wasit-standalone.html` مباشرة في المتصفح. يحتوي الملف على نسخة مجمعة من الواجهة ومحرك الصياغة.

الوظائف المحلية الأساسية تعمل دون خادم؛ أما المنصات الخارجية وخدمات الذكاء الاصطناعي فتحتاج إلى اتصال. الخطوط تُطلب من Google Fonts، وقد تظهر خطوط بديلة عند عدم الاتصال.

ملف `wasit-standalone.html` مستقل عن محتويات `dist`، ولا يعاد توليده تلقائيًا بواسطة أمر البناء الحالي.

### 3. معاينة النسخة المبنية محليًا

استخدم **Node.js 24**، وهو الإصدار المستخدم في إعداد النشر الحالي، مع npm ومتصفح حديث.

افتح PowerShell داخل مجلد المشروع:

<div dir="ltr">

```powershell
npm ci
npm run build
npm run preview
```

</div>

افتح العنوان الذي يطبعه Vite؛ افتراضيًا يكون:

<div dir="ltr">

```text
http://localhost:4173/
```

</div>

هذه الطريقة لمعاينة الواجهة ولا تتطلب مفتاح Gemini. لإيقاف الخادم اضغط `Ctrl + C`.

### 4. تشغيل خادم التطوير وتكامل Gemini

بعد تثبيت الحزم، جهز ملف البيئة في PowerShell إذا لم يكن موجودًا:

<div dir="ltr">

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

</div>

ضع مفتاحك في `.env`:

<div dir="ltr">

```dotenv
GEMINI_API_KEY=your_gemini_api_key_here
```

</div>

ثم شغل الخادم:

<div dir="ltr">

```powershell
npm run dev
```

</div>

العنوان الافتراضي هو `http://localhost:3000`. يمكن تغييره بمتغير `PORT`.

المعرّف المضبوط حاليًا للنموذج في `server.ts` هو `gemini-3.8-flash`. يعتمد نجاح الطلبات على إتاحة هذا المعرّف للحساب وصلاحية المفتاح.

ملفات `.env` مستبعدة بواسطة `.gitignore`. احتفظ بالمفتاح على الخادم؛ لا تضعه في كود الواجهة أو ملفات النشر الثابتة.

## النشر على GitHub Pages

### النشر التلقائي

1. من المستودع افتح **Settings → Pages**.
2. اختر **GitHub Actions** في حقل **Source**.
3. ارفع تحديثات المشروع إلى فرع `main`، مع `package-lock.json` وملف `.github/workflows/deploy.yml`.
4. تنفذ مهمة النشر التلقائية تثبيت الحزم بواسطة `npm ci`، ثم `npm run build`، ثم نشر محتويات `dist`.
5. تابع النتيجة من تبويب **Actions**.

يمكن أيضًا تشغيل المهمة يدويًا من صفحة سير العمل عبر **Run workflow**.

### النشر اليدوي على استضافة ثابتة

نفذ `npm run build`، ثم ارفع **محتويات مجلد `dist`** إلى الاستضافة.

يحتاج `index.html` الموجود في المصدر إلى البناء لتحويل Tailwind إلى CSS جاهز للمتصفح. رفع ملفات المصدر وحدها إلى استضافة ثابتة قد يؤدي إلى ظهور الصفحة بلا تنسيق.

يضبط `vite.config.ts` الخيار `base: './'` حتى تستخدم الملفات المبنية مسارات نسبية مناسبة لمجلد المشروع على GitHub Pages.

## هيكل المشروع

<div dir="ltr">

```text
wasit_prompt_studio/
├── .github/workflows/deploy.yml
├── .env.example
├── .gitignore
├── index.html
├── wasit-standalone.html
├── package.json
├── package-lock.json
├── vite.config.ts
├── tsconfig.json
├── server.ts
├── README.md
├── public/
├── src/
│   ├── catalog.js
│   ├── promptBuilder.js
│   ├── app.js
│   └── index.css
└── dist/
```

</div>

- `index.html`: بنية الواجهة الرئيسية.
- `src/catalog.js`: الأوامر والتصنيفات والقوالب والخيارات.
- `src/promptBuilder.js`: صياغة البرومبت ومواصفات المنتج وتدقيق المعطيات.
- `src/app.js`: التفاعل والحالة والحفظ المحلي والتصدير.
- `src/index.css`: Tailwind والتنسيقات المخصصة ومتغير الوضع الداكن.
- `server.ts`: خادم Express ومسارات Gemini.
- `public/`: ملفات ثابتة تنسخ إلى ناتج البناء.
- `dist/`: ناتج البناء الجاهز للنشر؛ يولد آليًا ومستبعد من Git.

## الاستخدام اليومي

1. اختر أمرًا أو قالبًا قريبًا من مهمتك.
2. اكتب الفكرة والجمهور والقيود المطلوبة.
3. راجع الإعدادات المتخصصة وصيغة المنتج.
4. فعّل تذييل البيانات إذا كنت تحتاج اسم المعلم أو المدرسة.
5. راجع ملاحظات التدقيق وأصلح ما يناسب المهمة.
6. انسخ البرومبت إلى منصتك المفضلة، أو نزله كنص، أو احفظ الإعدادات كقالب.

الملفات النصية المرفقة تقرأ محليًا عند تفعيل إدراج محتواها. ملفات PDF والصور يشار إليها بالاسم في البرومبت؛ لا يعني ذلك استخراج محتواها تلقائيًا.

## حل المشكلات الشائعة

- **الصفحة بلا ألوان أو بطاقات:** تحقق من نجاح البناء ونشر محتويات `dist`، ومن اختيار GitHub Actions مصدرًا لـ Pages.
- **تظهر نسخة قديمة:** حدّث الصفحة باستخدام `Ctrl + F5` بعد اكتمال النشر.
- **زر Gemini لا يعمل على GitHub Pages:** شغل الخادم مع إعداد الخدمة؛ الاستضافة الثابتة لا تشغل `server.ts`.
- **القوالب المحفوظة غير ظاهرة في متصفح آخر:** التخزين محلي لكل متصفح وموقع. استخدم تصدير المكتبة واستيرادها لنقل القوالب.
